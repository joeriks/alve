# Working on Alve

- Write documentation, UI copy, examples, and code identifiers in English.
- Keep the README honest about implemented behavior versus proposed behavior.
- Treat the memory graph, typed facts, and human-readable content as the product core.
- Do not add cloud storage, analytics, remote AI fallback, or automatic external context disclosure by default.
- Keep encryption, P2P synchronization, and AI authorization as separate responsibilities.
- Use established cryptographic implementations. Never invent cryptographic protocols or claim security based only on an AI instruction.
- Preserve user edits, conflicting revisions, and source provenance. Synchronization is not a backup.
- Never commit real memory data, credentials, keys, or private backups.
- Choose bounded, cost-effective delegation when useful: cost_luna for mechanical work, cost_terra for ordinary implementation, and cost_astra for consequential unresolved security or data-loss design. Workers must have separate edit ownership and must not revert others' changes. Do not delegate trivial work unnecessarily.
- Validate meaningful failure paths before claiming robust storage, synchronization, or recovery. A visual prototype does not verify those properties.
